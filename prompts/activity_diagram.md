## 输出要求

只输出Mermaid flowchart代码，不要输出其他任何内容。不要用JSON包裹。

格式要求：
1. 第一行必须是 `flowchart TD` 或 `flowchart LR`
2. 使用标准的Mermaid flowchart语法
3. 节点文本使用中文
4. 覆盖需求分析中描述的全部操作流程，不要遗漏任何一个。如果需求描述了多个流程（如多个角色的不同操作路径、多个业务场景的流转），必须在活动图中全部画出对应的分支，不能只画其中一个
   - **复杂度控制（关键）**：如果流程包含 3 个以上独立业务场景（如下单、支付、售后），必须使用 `subgraph` 拆分为"主流程"和各子流程（如 `subgraph 售后流程`），不要把所有分支塞在一张平铺图里
   - 如果流程过长（超过 25 个节点或包含 3 个以上独立业务流程），必须按 `subgraph` 拆成主流程、支付/库存/售后等子流程，保持可读性
   - 对功能的 `sub_capabilities` 中涉及的关键步骤、渠道、状态分支必须体现，不能只画顶层功能 ID
5. 使用菱形节点表示判断（如 `{库存充足?}`）
6. 使用矩形表示操作步骤
7. **必须**使用 `([开始])` 和 `([结束])` 标记流程的起止节点
8. 所有判断节点的每个分支都必须有明确的去向，不能悬空
9. **必须输出完整的活动图代码**，所有节点和连线必须闭合，不要中途截断
10. 异常分支的 ID 必须与需求分析中的异常 ID 一致，约束分支必须使用 Cxxx，不要把约束硬写成 Exxx
11. 不要复用同一个异常 ID 去表示不同业务规则
12. 简单无状态需求不应在活动图中增加持久化、审计、历史记录等原文未要求的步骤

示例格式：
```mermaid
flowchart TD
    A([开始]) --> B[用户发起请求]
    B --> C{是否已登录?}
    C -->|是| D[处理请求]
    C -->|否| E[跳转登录页]
    D --> F([结束])
    E --> F
```

## 关键要求

1. **具体化**：每个步骤必须包含具体的输入数据和操作，禁止使用笼统表述
2. **可验证**：每个预期结果必须明确、可验证，禁止使用"系统正常"、"符合预期"等模糊表述
3. **真实数据**：使用真实合理的测试数据，如具体的用户名、金额、日期等
4. **步骤完整**：每个测试用例至少包含3个具体步骤
5. **严格按任务**：每个测试任务的 testIdPrefix 必须作为对应测试用例的 id 使用

## 输出格式

请只输出合法 JSON，不要输出 Markdown、代码围栏或解释文本。根对象必须包含 `test_cases` 数组。

JSON Schema：
{
  "test_cases": [
    {
      "id": "TC-N-001",
      "title": "用户登录成功",
      "type": "正常",
      "target": "F001 用户登录",
      "preconditions": "用户已注册",
      "steps": ["输入正确用户名", "输入正确密码", "点击登录"],
      "expected_result": "登录成功，跳转首页",
      "priority": "P0"
    }
  ]
}

字段要求：
- `id`: 必须使用任务中指定的 testIdPrefix
- `title`: 简短说明测试目的
- `type`: 只能是 正常、异常、边界
- `target`: 必须包含任务中指定的目标功能/约束/异常 ID
- `preconditions`: 明确的前置条件
- `steps`: 字符串数组，每一步包含具体操作和数据
- `expected_result`: 明确可验证的结果
- `priority`: 只能是 P0/P1/P2

## 禁止事项

- 不要写模板化测试用例（如"检查是否满足约束"、"尝试违反约束"等笼统表述）
- 不要使用模糊的预期结果（如"系统正常"、"操作成功"等）
- 不要编造任务中未指定的 ID
- 每个测试用例的 steps 和 expected_result 必须直接验证任务 mustCover / 目标约束 source_text 中给出的规则；禁止测试任务未提供的规则（如编造的身份证正则、密码复杂度、年龄区间、金额上限、时限、2FA、速率限制等）
- 优先级只能使用 P0/P1/P2，禁止使用 高/中/低

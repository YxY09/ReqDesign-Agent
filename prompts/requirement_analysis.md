## 输出要求

请以JSON格式输出，包含以下字段：

```json
{{
  "project_name": "项目名称",
  "project_overview": "项目概述，1-2句话",
  "actors": [
    {{
      "name": "角色名称",
      "description": "角色描述"
    }}
  ],
  "functions": [
    {{
      "id": "F001",
      "name": "功能名称",
      "description": "功能描述",
      "related_actors": ["相关角色"],
      "priority": "高/中/低"
    }}
  ],
  "entities": [
    {{
      "name": "实体名称",
      "description": "实体描述",
      "attributes": ["属性1", "属性2"]
    }}
  ],
  "constraints": [
    {{
      "id": "C001",
      "description": "约束描述",
      "related_functions": ["相关功能"]
    }}
  ],
  "exceptions": [
    {{
      "id": "E001",
      "description": "异常流程描述",
      "trigger": "触发条件",
      "handling": "处理方式"
    }}
  ],
  "non_functional_requirements": [
    {{
      "category": "性能/安全/可用性等",
      "description": "需求描述"
    }}
  ],
  "business_processes": [
    {{
      "name": "流程名称",
      "steps": ["步骤1", "步骤2"],
      "actors": ["参与角色"]
    }}
  ]
}}
```

注意：
1. 只输出JSON，不要输出其他内容
2. 如果需求文档中没有提到某个字段的内容，使用空数组[]
3. 功能ID以F开头，约束ID以C开头，异常ID以E开头，按顺序编号
4. 尽量从需求文本中提取，不要过度推测
5. **功能提取注意事项**：
   - 需求文档中提到的每个独立功能点应单独列出，不要合并（如"注册"和"登录"应分开）
   - 功能名称应与需求文档中的用词保持一致
   - 每个功能点都应有独立的ID和描述
6. **实体(entities)**是指系统中需要存储和管理的核心业务对象，例如：用户、图书、订单、课程、会议室等。每个实体应包含名称、描述和关键属性列表。请务必从需求中识别并列出所有核心实体。
7. **实体提取注意事项**：
   - 需求文档中提到的不同角色（如员工、管理员、教师）应作为独立实体，不要合并为泛化的"用户"
   - 需求中提到的资源类对象（如设备、会议室、商品）应作为独立实体，不要仅作为其他实体的属性
   - 记录类对象（如预约记录、选课记录、借阅记录）应作为独立实体
   - 实体名称应与需求文档中的用词保持一致

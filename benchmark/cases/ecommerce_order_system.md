# 电商订单管理系统需求

## 项目概述

设计一个B2C电商订单管理系统，支持用户下单、支付、发货、退货退款等核心业务流程。系统需要处理高并发订单，同时保证数据一致性和交易安全。

## 用户角色

### 1. 顾客
- 注册登录、浏览商品
- 加入购物车、下单购买
- 查看订单、申请退款
- 评价已收货商品

### 2. 商家
- 管理商品上下架
- 处理顾客订单
- 查看销售报表
- 设置促销活动

### 3. 管理员
- 管理用户账号
- 审核商家资质
- 系统配置管理
- 数据统计分析

### 4. 仓库管理员
- 订单发货操作
- 库存管理
- 退货商品验收

## 功能需求

### 顾客模块（F001-F020）

#### F001: 用户注册与登录
- 支持手机号+验证码注册
- 支持密码登录和短信验证码登录
- 支持第三方登录（微信、支付宝）
- 登录后需绑定手机号

#### F002: 商品浏览
- 商品列表分页展示
- 按分类、价格、销量筛选排序
- 商品详情页展示库存、价格、评价
- 浏览历史记录

#### F003: 购物车
- 添加/删除/修改商品数量
- 勾选结算
- 合并多个店铺商品
- 购物车数据本地+服务器同步

#### F004: 订单创建
- 选择收货地址（支持新增/编辑/删除）
- 选择配送方式（普通/加急/次日达）
- 选择支付方式
- 使用优惠券/积分抵扣
- 订单金额自动计算（含运费）

#### F005: 订单支付
- 支持微信支付、支付宝、银行卡
- 支付超时自动取消订单（30分钟）
- 支付成功发送短信通知
- 支付结果轮询+回调双重确认

#### F006: 订单取消
- 顾客未付款可自主取消
- 付款后需申请退款
- 商家未发货可取消（需审核）
- 系统超时自动取消

#### F007: 申请退款/退货
- 仅退款（未发货）
- 退货退款（已发货/已收货）
- 上传凭证图片
- 退货需填写物流单号

#### F008: 商品评价
- 已收货订单可评价
- 支持文字+图片评价
- 匿名评价选项
- 追加评价功能

### 商家模块（F021-F040）

#### F021: 商品管理
- 新增/编辑/删除商品
- 设置SKU（颜色、尺寸等）
- 上下架管理
- 库存批量导入导出

#### F022: 订单处理
- 查看待发货订单
- 批量发货（支持电子面单）
- 订单标记异常
- 退款/退货审核

#### F023: 促销活动
- 满减活动（满X减Y）
- 折扣活动（X折起）
- 优惠券发放
- 秒杀/拼团设置

#### F024: 数据报表
- 销售额统计
- 订单量统计
- 商品销量排行
- 客户分析

### 系统模块（F041-F060）

#### F041: 库存管理
- 实时库存同步
- 库存预警（低于阈值通知）
- 库存锁定（下单后锁定）
- 出入库记录

#### F042: 消息通知
- 短信通知（阿里云/腾讯云）
- 站内信
- APP推送
- 邮件通知（可选）

#### F043: 日志与审计
- 操作日志记录

- 数据备份

## 业务流程

### B001: 正常下单流程
```
浏览商品 → 加入购物车 → 确认订单 → 选择地址 → 选择支付 → 提交订单 → 支付成功 → 等待发货 → 确认收货 → 评价完成
```

### B002: 退货退款流程
```
申请退款 → 商家审核 → 填写物流 → 仓库验收 → 退款处理 → 退款到账
```

### B003: 库存锁定流程
```
下单成功 → 库存锁定 → 支付成功 → 库存扣减 → 订单完成 → 释放未付款锁定库存
```

## 业务约束

### C001: 订单约束
- 单笔订单商品数量不超过99件
- 单笔订单金额不超过99999元
- 同一商品单次购买不超过10件
- 收货地址需在配送范围内

### C002: 支付约束
- 支付超时时间为30分钟
- 单笔支付限额根据支付方式不同
- 退款原路返回（72小时内到账）

### C003: 库存约束
- 库存不足时不可下单
- 活动期间库存可能超卖（最多5%）
- 库存预警值为10件

### C004: 用户约束
- 用户名4-20字符，不可重复
- 手机号需唯一
- 同一IP24小时内注册不超过5次

## 异常流程

### X001: 支付失败
- 触发条件：网络异常、余额不足、风控拦截
- 处理方式：提示用户重试，记录失败原因，发送告警通知

### X002: 库存不足
- 触发条件：下单时库存已售罄
- 处理方式：提示商品已售完，自动关闭订单，退还已付金额

### X003: 恶意下单
- 触发条件：同一用户短时间内大量下单
- 处理方式：加入风控黑名单，人工审核，限制购买

### X004: 商家延迟发货
- 触发条件：付款后72小时未发货
- 处理方式：自动补偿优惠券，发送安抚短信

### X005: 物流异常
- 触发条件：物流信息超过48小时未更新
- 处理方式：主动联系物流公司，更新用户状态，协助退款

### X006: 并发超卖
- 触发条件：高并发下库存扣减不一致
- 处理方式：使用分布式锁，保证库存扣减原子性

## 非功能需求

### N001: 性能要求
- 页面响应时间 < 2秒
- 核心接口（TPS）≥ 1000
- 订单处理峰值 ≥ 5000/秒
- 数据库查询优化，添加必要索引

### N002: 可用性要求
- 系统可用性 ≥ 99.9%
- 核心功能全年不可用时间 < 8.76小时
- 支持故障自动切换
- 定期灰度发布

### N003: 安全要求
- 用户密码加密存储（加盐+哈希）
- 敏感数据脱敏展示
- 请求签名验证
- SQL注入/XSS攻击防护
- 交易数据加密传输（HTTPS）

### N004: 可扩展性
- 支持水平扩展（增加服务器）
- 插件化设计，便于功能扩展
- 配置化促销规则
- 多租户架构预留

### N005: 可维护性
- 日志规范记录（结构化日志）
- 接口文档自动生成
- 代码模块化，低耦合
- 单元测试覆盖率 ≥ 80%
